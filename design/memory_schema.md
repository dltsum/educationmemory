# 结构化流程记忆设计 v0.1

> 场景: 中小学个性化辅导问答 | 基座: mimo-v2.5 / LongCat-2.0 (弱模型, 线性上下文幻觉严重)
> 设计目标: **把记忆从"LLM 自由文本回忆"变成"代码维护的结构化状态 + LLM 只读"**

## 0. 核心判断 (为什么线性叠加必死)

线性叠加上下文在弱模型上的失败链:
1. 上下文膨胀 → 注意力稀释 → 早期事实被遗忘/张冠李戴
2. 弱模型指代消解差 → "他/这道题/上次" 挂错实体 → 幻觉
3. 对话中的纠错/更新被淹没 → 旧错误事实与新事实并存 → 模型随机采信
4. 无遗忘机制 → 噪声与信号等权

**设计哲学: LLM 只做"抽取"和"消费", 不做"记忆管理"。记忆的合并、去重、冲突解决、衰减全部在代码层确定性完成。** 弱模型抽取也会错 → 每条记忆必须带来源(turn_id)与置信度, 支持审计与回滚。

## 1. 记忆总体架构: 四层 (Process-Structured Memory, PSM)

```
┌─────────────────────────────────────────────────┐
│ L0 事件流 EventLog (append-only, 原始证据)        │  每轮: {turn_id, role, text, ts}
├─────────────────────────────────────────────────┤
│ L1 事实层 FactStore (结构化三元组+来源)           │  抽取器从 EventLog 增量抽取
│   - student_profile: 姓名/年级/学校/教材版本...    │
│   - preferences: 讲题风格/例题偏好/鼓励方式...     │
│   - life_context: 考试时间/近期事件...            │
├─────────────────────────────────────────────────┤
│ L2 认知层 KnowledgeState (知识点 × 掌握度)        │  KT-lite: 每知识点
│   {kc_id, mastery∈[0,1], evidence[], last_seen, │
│    error_patterns[], forgetting_decay}          │
├─────────────────────────────────────────────────┤
│ L3 教学层 TutoringPlan (盲点/待办/推荐)           │  由 L2 确定性推导:
│   blind_spots[], next_focus, recommended_res[]  │  规则推导, 非LLM生成
└─────────────────────────────────────────────────┘
        写入路径: 每轮后 ExtractionPass (LLM→JSON, 严格schema)
        读取路径: 每轮前 ContextCompiler → 紧凑"学生卡片"注入
```

## 2. 关键机制

### 2.1 写入: Schema-Constrained Extraction (每轮一次 LLM 调用)
- 抽取 prompt 要求输出**固定 JSON schema**, 只允许: ADD / UPDATE / RETRACT 三种操作
- 每个字段强制携带 `evidence_turn_ids` —— 无来源的事实直接丢弃 (代码层校验)
- 弱模型容错: JSON 解析失败 → 重试1次(附错误信息) → 仍失败则本轮跳过并记日志(**显式失败**, 规则12)

### 2.2 合并与冲突解决 (纯代码, 无LLM)
- profile 字段: 单值槽位, 新值覆盖旧值, 保留历史版本 (versioned slot)
- 知识点掌握度: 简单贝叶斯/指数更新 `m ← m + α(correct-m)`, α 由证据强度定
- 遗忘: Ebbinghaus 近似 `retention = exp(-Δt/τ)`, 显示在卡片上 ("3天前学过, 可能已遗忘")

### 2.3 读取: Context Compiler (纯代码)
每轮注入的"学生卡片" ≤ ~400 tokens:
```
【学生】小明, 五年级, 人教版数学
【掌握】分数加减 0.85✓ | 分数乘除 0.42⚠ | 小数转换 0.61
【盲点】通分时找最小公倍数(2次错误, 最近: 8月30日)
【风格】喜欢先给提示再自己试; 讨厌直接给答案
【近期】9月5日期中考试
```
- 不在卡片里的 = 模型不该知道的 → 从机制上压幻觉
- 卡片内容全部来自结构化状态, 无自由文本摘要 → 无摘要漂移

### 2.4 盲点发掘与推荐 (L3, 规则推导)
- 盲点 = mastery<0.6 且 error_count≥2 的知识点, 按 "考试临近度×严重度" 排序
- 资源推荐: 知识点 → 预设资源库映射 (代码查表), LLM 只负责用自然语言包装

## 3. 与文献的对应 (详见 papers/survey_agent_notes.md)
- 分层: MemoryOS/H-Mem 的分层思想, 但按**教学流程**(事件→事实→认知→计划)而非按时长分层
- 遗忘: MemoryBank/TASA 的 Ebbinghaus
- 图谱: Mem0g/Zep 的 KG → 简化为知识点前置关系 DAG (中小学课标天然是 DAG)
- 写入门控: 安全综述指出的 write-gate/审计缺口 → evidence_turn_ids + 版本化

## 4. 评测设计 (T4/T5)
- 模拟学生: 脚本化 persona, 在 N=24 轮对话中按计划披露事实 F={f1..f20}、制造错题事件 E
- 探针: 第 8/16/24 轮后插入记忆探针问题 (直接回忆/跨轮推理/干扰项)
- 指标: 事实回忆准确率 / 幻觉率(虚构未出现事实) / KT 状态一致率
- 对照: A=线性全历史, B=PSM v0.1; 模型: mimo-v2.5, longcat-2.0 → 2×2

## 5. 已知风险与降级
- 弱模型抽取 JSON 失败率高 → 降级: 正则兜底抽取关键槽位 + 日志
- 知识点本体: 先手工定义小学数学 20 个知识点的 mini 本体, 不建全量课标
- API 速率: 每轮 2 次调用(回答+抽取), 24 轮×2模型×2方案 ≈ 200 次调用, 可接受
