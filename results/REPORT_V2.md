# REPORT V2 — 三层记忆机制实测报告 (2026-09-03)

## 需求与设计

用户指定三层机制（替代 v1 的全 LLM 抽取方案）：
1. **记忆保存**：本地、无 API、非强规则槽位。"过滤掉部分信息而不是只保留部分信息" → 实现为**默认全保留 + 仅剔除三类噪声**（fuzzy 去重 Jaccard≥0.85 / 子句级纯应答判定 / AI 样板话前缀），基本信息保真度最高。
2. **记忆整理**：LLM 调用，原始条目 → 分节结构化文档（画像/进展/错题/偏好/事件/待办），融合式更新 + NO-OP 门控（参考 Codex Phase 2）。
3. **记忆压缩**：LLM 调用，结构化文档 → 电报式高密度摘要，参考 `记忆.docx` 中 Codex `memory_summary.md` 的 progressive disclosure 原则（dense/navigational/discriminative）+ ALREADY-COMPACT 门控。

## 测试构造

- **真实数据集**: MathDial (HuggingFace `eth-nlped/mathdial`, NeurIPS 2023 D&B) 100 条真实师生数学对话，含 student_profile / 错误解法 / 多轮对话
- **长信息填充**: 1,470 字符合成学生档案（教务处导出风格：成绩史/行为观察/家庭/兴趣/备注），内嵌 8 个探测事实 + 干扰噪声 + 1 个"明确无宠物"反幻觉锚点
- 流程：档案注入 → 2 段 MathDial 对话重放（10 轮）→ 整理 → 压缩 → 三种记忆策略 × 10 探针（8 回忆 + 2 陷阱）

## 结果

| 模型 | 层 | 字符 | recall | halluc(审计后) |
|---|---|---|---|---|
| mimo-v2.5 | raw | 9,570 | 1.0 | 0 |
| mimo-v2.5 | organized | 1,446 (**-85%**) | 1.0 | 0 |
| mimo-v2.5 | compressed | 460 (**-95%**) | 0.875 | 0 |
| longcat-2.0 | raw | 9,092 | 1.0 | 0.5→**0** (评分器误报: 差值"降了2分"误匹配) |
| longcat-2.0 | organized | 854 (**-91%**) | 1.0 | 0 |
| longcat-2.0 | compressed | 423 (**-95%**) | 1.0 | 0 |

保存层统计: ~260 句入库, 去重 15–75 条（longcat 回复更啰嗦→重复更多）, 样板话 1 条。

## 发现

1. **整理层是纯收益**: -85~91% 字符，零准确率损失（两模型一致）。
2. **压缩层 -95%，保真度略降**: mimo 丢"猫毛过敏"细节，但**正确弃答而非编造**——压缩损失表现为"遗忘"，不表现为"幻觉"，这是理想退化模式。
3. **去重有效**: 长对话里教师鼓励和重复讲解产生大量近重复句，fuzzy dedup 稳定剔除。
4. **整理质量**: LLM 融合式整理能正确标注纠正关系（如成绩演变），无数字篡改（抽查 82/6分/7号/9月28日 全部保真）。

## 工程事故与修复（如实记录）

- **urllib 403 事件**: opencode go 网关对 Python urllib（经系统代理）一律 403，requests 正常 → 后端固定 requests。第一次 v2 全量结果因此作废删除。
- **评分器误报 2 例**: "降了2分"差值误匹配；已在 testbed 修复。
- 复合型应答"好的，谢谢！"漏删 → 子句级判定修复。

## 结论

三层机制成立：**保存层**保真兜底（本地、免费、无幻觉引入），**整理层**是性价比之王（-90% 成本、零损失），**压缩层**适合超长程/跨会话常驻（-95%、退化模式安全）。与 v1 结论一致：结构化记忆的价值在成本、可控性、可审计，而非短程准确率。
